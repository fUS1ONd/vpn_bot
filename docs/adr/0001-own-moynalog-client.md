# Свой HTTP-клиент «Мой налог» вместо готовой библиотеки

Для регистрации чеков в «Мой налог» пишем собственный клиент
(`internal/moynalog`) по образцу `internal/yookassa`, а не берём готовую
Go-библиотеку. Официального API у ФНС нет — используется закрытый
`https://lknpd.nalog.ru/api/v1`, тот же, на котором работает веб-кабинет.

## Considered Options

**`github.com/AlexZzz/nalogo-go`** (v0.1.1, MIT) — единственная найденная
Go-обёртка. Закрывает аутентификацию, создание и аннулирование чека, но **не
умеет получать список доходов** (`GET /incomes`), а он обязателен: это
единственный способ узнать, создался ли чек, когда ответ ФНС потерялся. При 11
коммитах и нуле форков это код одного автора вокруг недокументированного API —
чинить его пришлось бы всё равно самим, но через форк.

**Свой клиент.** Протокол известен целиком и сверен по двум независимым
реализациям (PHP `shoman4eg/moy-nalog`, JS `alexstep/moy-nalog`) плюс живыми
запросами. Объём — пять эндпоинтов.

## Consequences

Ломающие изменения закрытого API придётся ловить самим — но при отсутствии
живого сообщества вокруг альтернативы это верно в любом случае.

Ошибки разбираются по HTTP-статусам, а не по кодам: тело ошибки единообразно
(`{"code", "message", "additionalInfo"}`), но перечня кодов нет нигде, и
известные реализации тоже строят обработку на статусах.

Подробности протокола, включая формат дат в `GET /incomes` и особенности 500-го
ответа, зафиксированы в `docs/specs/2026-08-06-moynalog-receipts-design.md`.
