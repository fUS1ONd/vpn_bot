**Дата:** 2026-03-02

## Цели

1. Улучшить UX приглашений — один клик вместо ручного ввода кода
2. Добавить роль модератора — доверенные пользователи, которые могут приглашать других

## 1. Deep Link инвайты

### Проблема

Сейчас: админ создаёт код → копирует → отправляет человеку в чат → тот открывает бота → /start → вводит код. Много шагов.

### Решение

Telegram поддерживает параметр в `/start`. Бот при создании инвайта выдаёт готовую ссылку:

```
https://t.me/<bot_username>?start=a1b2c3d4
```

Человек кликает → бот получает `/start a1b2c3d4` → автоматически активирует код → готово.

> **Техническая деталь:** payload извлекается через `c.Message().Payload` (telebot v3 автоматически парсит часть после `/start `). Hex-коды (символы `0-9a-f`) совместимы с ограничениями Telegram deep link (допустимы `A-Z`, `a-z`, `0-9`, `_`, `-`, длина до 64 символов).

### Формат сообщения при создании (для админа и модератора)

Сообщение спроектировано для **пересылки** — самодостаточное, понятное и отправителю, и получателю:

```
🔒 Приглашение в VPN

Нажмите на ссылку ниже, чтобы активировать доступ:
👉 https://t.me/<bot_username>?start=a1b2c3d4
```

URL формируется через `b.bot.Me.Username` (доступен после создания бота в `tele.NewBot`).

Модератор/админ просто форвардит это сообщение нужному человеку.

### Изменения в `handleStart`

Новый flow с учётом deep link payload:

```
1. Извлекаем payload: code := c.Message().Payload
2. Проверяем пользователя в БД

3. Если пользователь существует:
   → игнорируем payload, показываем меню "С возвращением!"
   → код НЕ расходуется

4. Если пользователь новый И payload не пустой:
   → сразу вызываем processInviteCode(c, payload)
   → если код валиден — регистрация
   → если код невалиден — ошибка ("Код не найден" / "Уже использован"),
     устанавливаем StateWaitInvite чтобы пользователь мог ввести
     правильный код текстом

5. Если пользователь новый И payload пустой:
   → текущее поведение: StateWaitInvite, "Введите код"
```

Ручной ввод кода остаётся как fallback для случаев без deep link.

## 2. Система модераторов

### Роль модератора

Модератор — зарегистрированный пользователь бота с дополнительными правами:
- Создавать инвайт-коды (без лимита)
- Просматривать список своих приглашений (использованные и нет)
- Удалять свои неиспользованные коды (только свои, проверка `created_by`)

Модератор **НЕ может**: банить, добавлять трафик, делать рассылку, управлять другими модераторами.

### БД: таблица `moderators`

```sql
CREATE TABLE IF NOT EXISTS moderators (
    telegram_id INTEGER PRIMARY KEY,
    added_by INTEGER NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

Модератор обязательно должен быть уже зарегистрированным пользователем бота (проверка наличия в таблице `users` при назначении).

Таблица `invites` уже имеет поле `created_by` — оно показывает, кто создал код (админ или модератор).

### БД: новые методы

- `GetInvitesWithUsersByCreator(createdBy int64)` — инвайты конкретного модератора с данными пользователей
- `DeleteUnusedInviteByOwner(code string, createdBy int64)` — удаление только своего неиспользованного кода (SQL: `DELETE FROM invites WHERE code = ? AND used_by IS NULL AND created_by = ?`)

### UX модератора

В пользовательском меню появляется дополнительная кнопка:

```
👤 Мой статус    | 🌐 Подключить
📡 Серверы       | 📚 Инструкции
🎟 Приглашения
💸 Поддержать
```

При нажатии "Приглашения" открывается подменю:

```
📨 Создать приглашение
📋 Мои приглашения
🗑 Удалить приглашение
🔙 В меню
```

> **Кнопка "Назад":** текст `🔙 В меню` вместо `🔙 Назад`, чтобы не конфликтовать с существующей кнопкой `BtnBack` из подменю инструкций. Роутинг в `handleTextMessage` идёт по точному совпадению текста, поэтому все кнопки "назад" должны иметь уникальный текст.

#### Создать приглашение

Генерирует код, выдаёт сообщение для пересылки (формат из раздела 1).

#### Мои приглашения

Все коды модератора в одном сообщении:

```
📋 Мои приглашения (5)

⭕ Не использован
🔹 Код: a1b2c3d4
📅 Создан: 01.03.26 14:30

✅ Использован
🔹 Код: f5e6d7c8
👤 @username • Иван
📅 02.03.26 10:15

✅ Использован
🔹 Код: 11223344
👤 @petya • Петя
📅 28.02.26 09:00
```

#### Удалить приглашение

Запрашивает код → удаляет только свой неиспользованный код (через `DeleteUnusedInviteByOwner` с проверкой `created_by`).

### Админ-панель: управление модераторами

В меню "Управление" добавляется кнопка "Модераторы". Подменю:

```
➕ Назначить модератора
📋 Список модераторов
➖ Снять модератора
🔙 Назад
```

- **Назначить** — ввод telegram_id существующего пользователя бота
- **Список** — все модераторы (username, имя, telegram_id, количество приглашённых). Отображает `telegram_id` в формате `<code>` для копирования
- **Снять** — убирает права, человек остаётся обычным пользователем. Неиспользованные инвайты снятого модератора удаляются

### Просмотр инвайтов админом

В существующий список инвайтов админа (`handleViewInvites`) добавить отображение автора кода — чтобы было видно, какой модератор создал каждый инвайт.

## 3. Каскадные операции при бане/снятии модератора

### Бан пользователя (`processBanUser`)

При бане проверяем, является ли пользователь модератором. Если да:
1. Удаляем все неиспользованные инвайты этого модератора
2. Удаляем запись из таблицы `moderators`
3. Далее текущая логика: удаление из Remnawave + удаление из `users`

### Снятие модератора (без бана)

1. Удаляем все неиспользованные инвайты этого модератора
2. Удаляем запись из таблицы `moderators`
3. Пользователь остаётся в `users` и продолжает пользоваться VPN

## 4. Потокобезопасность `userStates`

Текущий `userStates map[int64]string` не защищён от конкурентного доступа. С добавлением модераторов (несколько привилегированных пользователей одновременно) вероятность race condition возрастает.

**Решение:** заменить `map[int64]string` на `sync.Map` или обернуть в `sync.RWMutex`. Сделать в рамках этой задачи, т.к. добавляем новые состояния для модераторов.
