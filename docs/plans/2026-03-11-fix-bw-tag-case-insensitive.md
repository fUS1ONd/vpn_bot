# План: регистронезависимый парсинг тега bandwidth

**Дата:** 2026-03-11

**Ветка:** `dev/fix-bw-indicator`

---

## Проблема

Remnawave API валидирует теги нод по паттерну `^[A-Z0-9_:]+$` — только uppercase.
Тег bandwidth в панели задаётся как `BW:1000`, но парсер `ParseBandwidthTag` ищет lowercase `bw:` — тег никогда не матчится и всегда возвращается дефолт (1000 Mbps).

Баг незаметен когда все ноды имеют bandwidth 1000 Mbps (дефолт совпадает), но при `BW:500` или `BW:1500` нагрузка считается неправильно.

## Затронутые файлы

| Файл | Изменение |
|------|-----------|
| `internal/monitoring/sync.go` | `ParseBandwidthTag` — привести тег к uppercase перед сравнением |
| `internal/monitoring/sync_test.go` | Новый файл — тесты для всех вариантов регистра и edge cases |

## Решение

Перед сравнением привести тег к uppercase через `strings.ToUpper(tag)`, чтобы работали любые варианты: `bw:`, `BW:`, `Bw:`, `bW:`.

## Тест-кейсы

- `BW:1000` → 1000
- `bw:500` → 500
- `Bw:1500` → 1500
- `bW:2000` → 2000
- Тег среди других → корректный парсинг
- Без тега / пустой / nil → дефолт 1000
- Невалидное / нулевое / отрицательное значение → дефолт 1000
