# План: тестовая оплата для администратора

## Цель

Дать администратору в пользовательском режиме возможность пройти реальный платёжный flow по отдельной тестовой цене из окружения, не меняя цены и доступность оплаты для остальных пользователей.

## Решение

- Добавить необязательную переменную `ADMIN_TEST_PAYMENT_PRICE`.
- Когда она задана положительным числом, для `ADMIN_ID` показывать кнопку оплаты даже при `subscription_price = NULL` и бессрочной подписке.
- Помечать такой платёж как тестовый. Он проверяет создание, redirect и callback, но не изменяет срок/статус подписки, не создаёт earnings, не попадает в финансовую статистику и при chargeback не банит администратора.
- Не задавать цену или задать `0` — сохранять текущее поведение: тестовая кнопка скрыта.
- Сохранить существующие ограничения: нужен зарегистрированный пользователь, активный провайдер, выключенный maintenance mode; запись будет обычным платежом без moderator earnings.

## Проверка

1. Покрыть загрузку переменной и отключение при некорректном значении.
2. Покрыть видимость кнопки, сумму и тестовую метку создаваемого платежа для администратора.
3. Покрыть безопасную обработку успешного callback и chargeback без изменения доступа администратора.
4. Выполнить `make fmt` и `make tests`.
