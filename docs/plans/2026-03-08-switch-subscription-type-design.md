# Перевод подписки с месячной на бессрочную

**Дата:** 2026-03-08
**Статус:** утверждён

## Цель

Админ может перевести пользователя с месячной подписки (модераторский инвайт) на бессрочную. Сценарий: модератор пригласил человека, который важен админу (родственник и т.п.), и админ не хочет каждый месяц продлевать ему подписку.

## Ограничения

- Операция доступна **только админу**
- Только в одну сторону: месячная -> бессрочная (обратной операции нет)
- Инвайт остаётся за модератором (`created_by` не меняется), но `expire_days` обновляется на `NULL`
- Пользователь **не** уведомляется о переводе

## Flow взаимодействия

1. Админ нажимает "Сменить тариф" в главном меню админки
2. Бот просит ввести telegram_id пользователя
3. Бот проверяет валидность (см. граничные случаи)
4. Бот показывает карточку подтверждения:
   ```
   Перевод на бессрочный тариф:
   Имя: Иван (@ivan)
   Куратор: @moderator
   Текущий срок: до 15.04.2026

   Перевести на бессрочную подписку?
   ```
5. Админ подтверждает — "Да" / "Отмена"
6. Бот выполняет перевод и отчитывается

## Технические изменения

### База данных (`internal/database/invites.go`)

Новый метод:
- `UpdateInviteExpireDays(usedBy int64, expireDays *int)` — обновляет `expire_days` в инвайте по `used_by`

### Админ-панель (`internal/bot/admin.go`)

- Новая кнопка "Сменить тариф" в главном меню админки
- Обработчик `handleSwitchSubscription()` — запрашивает telegram_id
- Обработчик `processSwitchSubscription()` — валидация, карточка, подтверждение

### Remnawave клиент

Новых методов не нужно. Переиспользуем `UpdateUser()` и `EnableUser()`.

### Scheduler

Изменений не нужно. Уже пропускает пользователей с `expireAt.Year() >= 2099`.

## Порядок операций при подтверждении

1. Если статус в Remnawave EXPIRED/DISABLED — `EnableUser(uuid)`
2. PATCH в Remnawave: `expireAt = 2099-01-01T00:00:00Z`
3. UPDATE в БД: `invites.expire_days = NULL`
4. Очистить `notifications_sent` для этого пользователя

Если Remnawave обновился, а БД нет — безопасно: scheduler увидит `expireAt=2099` и пропустит.

## Граничные случаи

| Случай | Поведение |
|--------|-----------|
| Пользователь уже бессрочный (`expire_days == NULL`) | "Этот пользователь уже на бессрочном тарифе" |
| Пользователь не найден в БД бота | "Пользователь не найден" |
| Пользователь забанен | "Этот пользователь забанен" |
| Пользователь кикнут (автокик) | "Пользователь не найден" (нет в БД бота) |
| Пользователь EXPIRED, но в grace period | Валидный кейс — `EnableUser()`, затем `expireAt=2099` |
| Инвайт не найден (legacy/мигрированный) | "Инвайт для этого пользователя не найден" |
| Remnawave API недоступен | "Ошибка при обновлении подписки, попробуйте позже". БД не обновляется |
