# Дизайн: оперативная обратная связь (багрепорт)

Дата: 2026-06-05
Ветка: `feature/bug-report`

## Цель

Дать пользователю простой способ сообщить, что какой-то сервер не работает,
а администратору — собрать структурированную информацию о проблеме без ручного
выяснения деталей.

## Принципы

- Минимум кликов для пользователя, UX-понятно.
- Данные пользователя (TG ID, имя, статус подписки) бот подставляет сам.
- Доставка — только администратору в личку (как `notifyAdminNewUser`). Без таблиц БД.
- Доступ только зарегистрированным пользователям + кулдаун от флуда.

## UX-флоу

Точка входа — новая reply-кнопка **«🛠 Сообщить о проблеме»** в главном меню
(показывается только зарегистрированным пользователям).

1. **Старт.** Юзер жмёт кнопку. Бот проверяет регистрацию и кулдаун, грузит хосты
   (`GetAllHosts`), ставит сессию и шлёт сообщение *«На каком сервере проблема?»* с
   **inline-кнопками** по `Remark` каждого хоста + «🤷 Не знаю / все сразу» + «🚫 Отмена».
2. **Выбор сервера.** Callback сохраняет сервер в сессию, бот редактирует сообщение,
   показывает **inline-категории**: `🔌 Не подключается`, `🐢 Медленно`,
   `🌍 Не грузит сайт`, `✍️ Другое`.
3. **Выбор категории.** Callback сохраняет категорию, убирает inline-клавиатуру и
   **отдельным reply-сообщением** просит описать проблему с кнопками
   `⏭ Пропустить` / `🚫 Отмена`. Состояние → `StateWaitBugComment`.
4. **Комментарий.** Текст или «Пропустить» → бот формирует репорт, шлёт админу,
   отвечает *«✅ Спасибо! Сообщение отправлено»*, чистит сессию/состояние, ставит
   метку кулдауна, возвращает в главное меню.

Смешение reply- и inline-разметки в разных сообщениях — как уже принято в проекте
для управления устройствами (Telegram не допускает обе разметки в одном сообщении).

## Состояние и сессии

В `Bot` добавляются (по образцу `modChangePriceData`):

```go
bugReportMu       sync.RWMutex
bugReportData     map[int64]bugReportSession // pending-данные багрепорта
bugReportCooldown sync.Map                   // telegram_id -> time.Time последней отправки
```

```go
type bugReportSession struct {
    server   string // Remark выбранного хоста или "" = "не знаю/все"
    category string // выбранная категория
}
```

Новое состояние: `StateWaitBugComment`. Выбор сервера и категории — через
inline-callback (отдельные wait-состояния не нужны).

Кулдаун: 10 минут на пользователя (in-memory).

## Формат сообщения админу

```
🛠 Багрепорт

📅 05.06.26 14:32
👤 Иван (@ivan) · tg://user?id=12345
📡 Сервер: 🇳🇱 Нидерланды
🔌 Проблема: Не подключается
💬 «второй день не коннектится»

Подписка: оплачена до 12.06.26
```

Статус подписки бот вычисляет из Remnawave (оплачена/триал/grace/нет).

## Edge-cases

- **Нет хостов / ошибка `GetAllHosts`** — пропускаем шаг выбора сервера, сразу
  категории, в репорте `📡 Сервер: не указан`.
- **Кулдаун активен** — алерт «Вы недавно уже отправляли», флоу не стартует.
- **Отмена на любом шаге** — чистим сессию + состояние, возврат в меню.
- **Брошенная сессия** — нажатие любой кнопки меню в `StateWaitBugComment`
  сбрасывает состояние (как payment-flow); новый старт перезаписывает сессию.
- **Устаревшие inline-данные** — сервер кодируется индексом, ресолвится из свежего
  `GetAllHosts`; промах → «не указан».
- **Сбой отправки админу** — логируем, юзеру всё равно «Спасибо».
- **Длинный комментарий** — обрезаем до ~1000 символов.

## Антискоуп (YAGNI)

- Без таблиц БД и аналитики (только личка админа).
- Без выбора сервера reply-кнопками (только inline).
- Без редактирования/отзыва уже отправленного репорта.
