# Тестовый стенд

Стенд поднимает бота с заглушкой панели Remnawave: настоящая панель не нужна.
Годится, чтобы прогнать пользовательский flow руками, снять скриншоты
интерфейса и проверить платёжный путь на тестовом магазине ЮKassa.

## Изоляция от прода

Стенд живёт в отдельном compose-проекте (`-p vpn-bot-test`), со своей сетью,
своими контейнерами и своей папкой данных `./data-test`. Прод-контейнеры он не
видит и не останавливает.

Два условия, нарушение которых стоит дорого:

- **Свой `BOT_TOKEN`.** Отдельный бот у @BotFather. С боевым токеном стенд
  перехватит апдейты у боевого бота: Telegram отдаёт каждый апдейт одному
  получателю.
- **Тестовый магазин ЮKassa.** С боевыми ключами спишутся настоящие деньги.
  На тестовом магазине автоплатежи доступны по умолчанию, согласование не нужно.

Команды всегда с явными `-p` и `-f`: без них docker compose подхватит
`docker-compose.yml` и остановит боевые контейнеры.

## Запуск

```bash
cp .env.test.example .env.test   # заполнить BOT_TOKEN, ADMIN_ID и ключи тестового магазина
docker compose -p vpn-bot-test -f docker-compose.test.yml --env-file .env.test up -d --build
docker compose -p vpn-bot-test -f docker-compose.test.yml logs -f
```

Остановить и убрать данные:

```bash
docker compose -p vpn-bot-test -f docker-compose.test.yml down
rm -rf data-test
```

## Заглушка панели

`cmd/mockpanel` — HTTP-сервер, отвечающий на те эндпоинты Remnawave, которые
использует бот: метаданные, список и карточка пользователя, создание,
обновление, перевыпуск ссылки, устройства, ноды, хосты. Состояние держится в
памяти и умирает вместе с контейнером.

`MOCK_PANEL_VERSION` задаёт контракт, который увидит бот: `2.8.1` (пользователь
адресуется UUID) или `3.2.3` (числовым `id`). Обе ветки проверяются одним
стендом.

Запустить отдельно, без докера:

```bash
MOCK_PANEL_PORT=8081 go run ./cmd/mockpanel
```

## Пульт: подкрутить срок, статус и трафик

Часть поведения бота висит на времени: уведомления за 3 дня и за сутки,
истечение подписки, grace-кик, ветки карточки «Моя подписка». Ждать их вживую
нельзя, поэтому у заглушки есть рычаги, которых у настоящей панели нет.

`POST /mock/user` находит пользователя по `telegramId` и меняет ему поля.
Префикс `/mock/` намеренно не похож на `/api/`: это пульт стенда, а не контракт
Remnawave.

```bash
# Подписка кончается через 60 часов — окно уведомления «за 3 дня»
curl -X POST localhost:8081/mock/user -d '{"telegramId":123456,"expireInHours":60}'

# Через 12 часов — окно «за 1 день»
curl -X POST localhost:8081/mock/user -d '{"telegramId":123456,"expireInHours":12}'

# Час назад — истечение и начало grace-периода
curl -X POST localhost:8081/mock/user -d '{"telegramId":123456,"expireInHours":-1}'

# 73 часа назад — grace-кик
curl -X POST localhost:8081/mock/user -d '{"telegramId":123456,"expireInHours":-73}'

# Триал с исчерпанным трафиком: карточка покажет «Лимит трафика исчерпан»
curl -X POST localhost:8081/mock/user -d '{"telegramId":123456,"usedTrafficGB":1.5}'

# Принудительный статус: ACTIVE, DISABLED, LIMITED, EXPIRED
curl -X POST localhost:8081/mock/user -d '{"telegramId":123456,"status":"DISABLED"}'
```

Срок задаётся **относительно «сейчас»**, а не датой: все окна планировщика
считаются от текущего момента, и с абсолютной датой пришлось бы каждый раз
считать руками.

### Как заставить планировщик сработать сразу

Плановый проход идёт раз в 30 минут, но **первый — сразу при старте**. Поэтому
после правки срока проще перезапустить контейнер бота, чем ждать:

```bash
docker compose -p vpn-bot-test -f docker-compose.test.yml restart vpn-bot-test
```

### Повторная проверка того же уведомления

Уведомления дедуплицируются таблицей `notifications_sent`: второй раз то же
самое не придёт. Чтобы прогнать сценарий заново, проще всего снести базу стенда
целиком и зарегистрироваться по новому инвайту:

```bash
docker compose -p vpn-bot-test -f docker-compose.test.yml down && rm -rf data-test
```

## Проход по автопродлению

1. `/start` в тестовом боте, активировать инвайт (создаётся в админке стенда под
   `ADMIN_ID`).
2. «💳 Оплатить подписку» → «⚡ Карта / СБП / SberPay». На экране выбора видно
   абзац согласия на сохранение способа оплаты.
3. Оплатить тестовой картой ЮKassa. Способ автосписания сохранится.
4. «👤 Моя подписка» → «🔄 Автопродление» и «💳 Способ оплаты» — оба экрана.
5. «💳 Способ оплаты» → «🗑 Отвязать» → подтверждение. Это те два экрана, которые
   ЮKassa просит приложить к заявке на подключение рекуррентов.

Шаг 3 требует, чтобы вебхук ЮKassa доставал до стенда. Если наружу его не
пробрасывать (ngrok, cloudflared), платёж подтвердится кнопкой
«🔄 Проверить оплату» — она ходит в API кассы сама.
