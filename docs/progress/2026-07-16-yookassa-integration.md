## Статус: план согласован, реализация не начата

Зафиксированы цель, UX и архитектурные границы интеграции ЮKassa как второго
провайдера. Выбран интерфейс: ЮKassa для рублёвых методов через собственную
страницу оплаты, Platega — для криптовалюты.

Код, конфигурация Docker, схема БД и Caddy в этом шаге не менялись.

## Зафиксированные внешние точки

- Входящий webhook ЮKassa: `POST /yookassa/webhook`.
- Публичный адрес для кабинета ЮKassa: `https://sarvizza.com/yookassa/webhook`.
- Существующий endpoint Platega сохраняется: `POST /platega/callback`.
- `return_url` будет задаваться на каждый новый платёж и ведёт в текущего
  Telegram-бота; он не служит подтверждением оплаты.

## Перед началом реализации

Нужны решения по комиссии ЮKassa, фискализации и политике возвратов. Затем
выполнять шаги 1-7 плана последовательно с тестами на каждом затронутом уровне.
