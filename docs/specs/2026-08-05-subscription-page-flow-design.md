# Переход на страницу подписки: реструктуризация пользовательского flow

Дата: 2026-08-05
Статус: согласовано, готово к планированию

## Проблема

Бот держит собственные инструкции по подключению — три захардкоженных экрана
(iOS / Android / ПК) в `internal/bot/messages.go`, меню `InstructionsKeyboard` и
reply-кнопку «📚 Инструкции» в главном меню. Эти тексты дублируют содержимое
страницы подписки Remnawave (subscription page), на которую и так указывает
`subscriptionUrl` каждого пользователя. Страница определяет платформу сама,
показывает нужные приложения и подключает в один тап, а её содержимое
настраивается через панель — без релиза бота.

Дублирование означает, что инструкции в боте устаревают молча: обновление
приложений или шагов в панели никак не доходит до пользователя.

## Решение

Убрать собственные инструкции целиком и сделать точкой входа страницу подписки,
открываемую inline URL-кнопкой. Заодно свернуть лишний уровень навигации:
«👤 Моя подписка» становится единственным экраном, где живёт всё, что касается
подключения — статус, ссылка, переход на страницу, устройства и перевыпуск
ссылки.

### Почему inline URL-кнопка, а не Telegram Mini App

Mini App открывает страницу внутри Telegram и выглядит бесшовно, но: домен
подписки использует нестандартный порт (`SUB_PUBLIC_DOMAIN=sub.fus1ond.ru:8443`),
который Telegram может не принять в поле WebApp; внутри Mini App deep-link'и в
приложения (`happ://`) часто блокируются — то есть главная кнопка страницы
«подключить» может не сработать. URL-кнопка отдаёт страницу браузеру, где
deep-link'и работают штатно, и не предъявляет требований к домену.

## Как бот получает ссылку

Бот ссылку не конструирует. Поле `SubscriptionURL` (`internal/remnawave/client.go:63`)
приходит готовым в ответе `GET /api/users/{uuid}`; строит его панель из своей
переменной `SUB_PUBLIC_DOMAIN` и `shortUuid` пользователя. Менять что-либо на
стороне панели не требуется.

## Экран «👤 Моя подписка»

Одно сообщение: текст статуса (как сейчас) + подпись + ссылка в `<code>` +
inline-клавиатура.

```
👤 Ваш статус

Тип: 💳 Подписка
Статус: ✅ Активен
Осталось: 24 дн. (до 29.08)
Трафик за месяц: 12.40 GB
Устройства: 2 / 3

Ссылка для ручного подключения
(нажмите, чтобы скопировать):
sub.fus1ond.ru:8443/xacqHr-…      ← <code>, не кликабельная
──────────────────────────
[ 🔗 Подключить устройство ]      ← URL → subscriptionUrl
[ 📱 Мои устройства ]             ← cbDevicesManage (существующий)
[ 🔄 Перевыпустить ссылку ]       ← cbSubRevoke → подтверждение
```

Ссылка остаётся моноширинной (`<code>`) и не кликабельной: тап по ней копирует
текст — это нужно для ручного добавления подписки в клиент.

Reply-клавиатура главного меню остаётся снизу нетронутой, поэтому
reply-подменю подписки больше не нужно: `SubscriptionMenuKeyboard` и reply-кнопка
`BtnDevices` («📱 Управление устройствами») удаляются вместе с уровнем навигации
«подписка → подменю → назад».

### Условия видимости

Кнопки «Подключить устройство» и «Перевыпустить ссылку», а также блок со ссылкой
показываются ровно там, где сейчас показывается ссылка подписки:

| Состояние | Ссылка + кнопки |
|---|---|
| Безлимитная (`formatInfiniteStatus`) | да, всегда |
| Trial / оплаченная при `StatusActive` | да |
| Trial с исчерпанным трафиком (`LIMITED`) | нет |
| Grace-период (`formatGraceStatus`) | нет, только призыв оплатить |

Логика видимости не меняется — кнопки просто следуют за ссылкой. Кнопка
«📱 Мои устройства» показывается всегда, когда пользователь зарегистрирован.

## Перевыпуск ссылки

Кнопка «🔄 Перевыпустить ссылку» ведёт на экран подтверждения, который прямым
текстом называет последствия: старая ссылка перестанет работать немедленно, все
подключённые устройства отвалятся и их придётся настроить заново. Кнопки
`[✅ Да, перевыпустить]` / `[🔙 Отмена]`.

### Порядок операций

1. `DeleteAllUserHwidDevices(uuid)` — сброс HWID-привязок.
2. `POST /api/users/{uuid}/actions/revoke` с телом `{}` — панель генерирует новый
   `shortUuid` сама (передавать свой не следует). Ответ содержит полного
   пользователя с уже новым `subscriptionUrl`, поэтому повторный `GetUser` не
   нужен — карточка перерисовывается через `c.Edit` данными из ответа.

Порядок важен. Если сброс устройств упадёт — состояние не тронуто, показываем
ошибку, ссылка прежняя. Обратный порядок опаснее: при падении сброса пользователь
остался бы с новой ссылкой и старыми HWID-привязками, переподключился и упёрся в
лимит устройств — чинить пришлось бы вручную. При выбранном порядке худший исход
(revoke упал после успешного сброса) — устройства сброшены, ссылка прежняя:
пользователь переподключается по старой ссылке и при желании повторяет перевыпуск.

### Защита от повторов

Дабл-клик по inline-кнопке — обычное дело, а каждый лишний перевыпуск рвёт
пользователю связь. По образцу существующего `adminExtendCooldown`
(`internal/bot/admin_extend.go`): поле `subRevokeCooldown sync.Map` в `Bot`
(telegram_id → время последнего успешного перевыпуска), окно 5 минут. Повторное
подтверждение внутри окна не дёргает API и отвечает алертом «Ссылка уже
перевыпущена, повторное нажатие проигнорировано».

## Регистрация

`MsgAccountCreated` сейчас заканчивается фразой «Нажмите "📚 Инструкции" для
настройки» — после удаления кнопки это станет ложью. Сообщение получает ту же
пару «ссылка `<code>` + inline-кнопка на страницу», чтобы новый пользователь
подключился прямо из приветствия, ничего не разыскивая в меню.

## Обработка ошибок

**Битый или пустой `subscriptionUrl`.** Перед сборкой клавиатуры URL проверяется
через `url.Parse` и на схему `http`/`https`. Не прошёл — inline-кнопки перехода
просто нет, блок со ссылкой в тексте остаётся.

**Telegram отклонил URL-кнопку.** Домен подписки содержит нестандартный порт
(`:8443`). Если Bot API по какой-то причине не примет такой URL, ошибка вернётся
на всё сообщение — пользователь не увидит даже своего статуса. Поэтому при ошибке
отправки сообщение повторяется тем же текстом без inline-клавиатуры. Статус
доходит всегда.

**Ошибки Remnawave при перевыпуске** отвечают алертом на callback; текст
различается для падения сброса устройств и падения самого revoke, чтобы
пользователь понимал, изменилось ли что-то.

## Навигация в устройствах

`handleDevicesManage` (`internal/bot/devices.go:43`) уже является
callback-хендлером на `cbDevicesManage`, редактирует текущее сообщение и умеет
фоллбэк на `Send` — подключается к карточке без переделок.

Меняется только выход: сейчас «🔙 Закрыть» (`handleDevicesClose`) удаляет
сообщение, а поскольку экран устройств теперь редактирует карточку подписки, это
стирало бы её. Кнопка становится «🔙 Назад» и возвращает карточку подписки на
место через `c.Edit`.

## Что удаляется

Из `internal/bot/handlers.go`: `handleInstructionsMenu`, `handleInstructionIOS`,
`handleInstructionAndroid`, `handleInstructionDesktop`, `getSubLinkForUser`,
ветки `switch` для кнопок инструкций и `BtnDevices`.

Из `internal/bot/keyboards.go`: `InstructionsKeyboard`, `SubscriptionMenuKeyboard`,
константы `BtnInstructions`, `BtnInstIOS`, `BtnInstAndroid`, `BtnInstDesktop`,
`BtnDevices`.

Из `internal/bot/messages.go`: `MsgInstructions`, `MsgInstructionIOS`,
`MsgInstructionAndroid`, `MsgInstructionDesktop`, а также `MsgSubscriptionLink`
(мёртвая константа, нигде не используется).

Тесты инструкций из `handlers_test.go` и соответствующие проверки в
`keyboards_test.go`.

Контент удаляемых текстов (ссылки на App Store, Play Market, APK, happ.su и шаги
настройки) покрыт страницей подписки — подтверждено владельцем сервиса.

## Новый код

- `internal/remnawave/client.go` — метод `RevokeUserSubscription(uuid string) (*User, error)`.
- `internal/bot/keyboards.go` — `SubscriptionCardKeyboard(subURL string, showConnect bool) *tele.ReplyMarkup`
  и `SubscriptionRevokeConfirmKeyboard()`; callback-константы `cbSubRevoke`,
  `cbSubRevokeConfirm`, `cbSubRevokeCancel`.
- `internal/bot/subscription_card.go` — сборка карточки, хендлеры перевыпуска,
  кулдаун. Выделен отдельным файлом, чтобы не наращивать `handlers.go`.
- `internal/bot/messages.go` — подпись к ссылке, текст экрана подтверждения,
  текст результата перевыпуска.

## Тестирование

- `SubscriptionCardKeyboard`: кнопка перехода присутствует при валидном URL и
  отсутствует при пустом, битом и не-http(s) URL; состав кнопок при
  `showConnect=false`.
- Формат статуса: подпись со ссылкой присутствует в active/infinite и отсутствует
  в grace и при исчерпанном трафике.
- Перевыпуск: успешный путь (устройства сброшены, revoke вызван, карточка
  перерисована новым URL); падение `DeleteAllUserHwidDevices` не приводит к вызову
  revoke; падение revoke после успешного сброса отдаёт свой текст ошибки;
  повторное подтверждение внутри окна кулдауна не дёргает API.
- Регистрация: `MsgAccountCreated` не упоминает кнопку «Инструкции» и содержит
  ссылку.
