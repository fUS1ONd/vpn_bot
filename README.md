# VPN Bot - Telegram бот для управления VPN подписками

Telegram бот для управления VPN-клиентами через 3X-UI панели с поддержкой трёх независимых серверов. Написан на Go 1.25 для максимальной производительности и простоты развертывания. Включает встроенный HTTP сервер подписок, поддержку четырёх типов промокодов и систему управления трафиком с автоматическим обновлением.

## Возможности

- Управление VPN-клиентами через интерфейс Telegram
- Автоматическая генерация VLESS ссылок с XTLS-Vision шифрованием
- HTTP(S) сервер подписок с автоматическим обновлением конфигураций
- Отслеживание трафика пользователей на каждом сервере
- Поддержка трёх серверов 3X-UI (Server A, Server B, Server C) с разными лимитами и конфигурациями
- Система промокодов (бесплатные дни, дополнительный трафик, скидки, неограниченный доступ)
- Пробный период с автоматической активацией
- Админ-панель для управления клиентами и промокодами
- Рассылка сообщений пользователям (текст, фото, видео, документы)
- База данных SQLite с веб-интерфейсом для просмотра данных
- GitHub Actions CI/CD с автоматическим деплоем на VPS через Docker Hub

## Работа с базой данных

База данных SQLite хранится в Docker volume `vpn_data`. Это обеспечивает сохранность данных даже при пересоздании контейнеров.

### SQLite Web UI

Для удобного просмотра и управления базой данных предусмотрен веб-интерфейс:

#### Запуск SQLite Web UI
```bash
docker compose --profile tools up -d
```

После запуска интерфейс будет доступен по адресу: http://localhost:8080

#### Остановить SQLite Web UI
```bash
docker compose --profile tools down
```

### Работа с volume

#### Посмотреть информацию о volume
```bash
docker volume inspect vpn_bot_vpn_data
```

#### Сделать бэкап базы данных
```bash
# Создать директорию для бэкапов
mkdir -p backups

# Скопировать БД из volume в локальную директорию
docker run --rm -v vpn_bot_vpn_data:/data -v $(pwd)/backups:/backup alpine cp /data/users.db /backup/users_$(date +%Y%m%d_%H%M%S).db
```

#### Восстановить базу данных из бэкапа
```bash
# Остановить бота
docker compose down

# Восстановить БД из бэкапа
docker run --rm -v vpn_bot_vpn_data:/data -v $(pwd)/backups:/backup alpine cp /backup/users_backup.db /data/users.db

# Запустить бота
docker compose up -d
```

#### Очистить все данные (ОСТОРОЖНО!)
```bash
# Остановить все контейнеры
docker compose down

# Удалить volume с данными
docker volume rm vpn_bot_vpn_data

# Запустить заново (создастся новая пустая БД)
docker compose up -d
```

## Переменные окружения

### Обязательные параметры

**Telegram:**
- `BOT_TOKEN` - токен Telegram бота (получить у @BotFather)
- `ADMIN_ID` - Telegram ID администратора (получить у @userinfobot)

**Сервер подписок:**
- `SUBSCRIPTION_HOST` - домен или IP для ссылок подписок (формат: `example.com` или `1.2.3.4`)
- `SUB_PORT` - порт сервера подписок (по умолчанию 8000)

**Серверы 3X-UI (SERVER_A, SERVER_B, SERVER_C):**

Для каждого сервера требуются переменные вида `SERVER_X_*`:
- `SERVER_X_BASE_URL` - URL панели 3X-UI (например, `https://1.2.3.4:2053`)
- `SERVER_X_WEB_PATH` - веб-путь панели (например, `/xxui` или `/admin`)
- `SERVER_X_USERNAME` - логин для панели
- `SERVER_X_PASSWORD` - пароль для панели
- `SERVER_X_INBOUND_ID` - ID входящего соединения в панели (обычно 1)
- `SERVER_X_LIMIT_BYTES` - лимит трафика в байтах (0 = безлимит). Пример: 32212254720 ≈ 30GB
- `SERVER_X_PUBLIC_KEY` - публичный ключ XTLS
- `SERVER_X_SNI` - SNI для TLS (например, `music.yandex.ru` или `google.com`)
- `SERVER_X_SID` - Short ID для VLESS

Все три набора переменных (SERVER_A, SERVER_B, SERVER_C) ОБЯЗАТЕЛЬНЫ для корректной работы.
Для каждого пользователя создаются аккаунты на всех трёх серверах с одним UUID.

### Опциональные параметры

- `DB_PATH` - путь к файлу базы данных (по умолчанию `/app/data/users.db`)
- `SQLITE_WEB_PORT` - порт веб-интерфейса SQLite (по умолчанию 8080, используется с `--profile tools`)

### Автоматическое развертывание (CI/CD)

Проект включает GitHub Actions workflow для автоматического развертывания на VPS:

#### Как это работает:
1. При push в branch `main`:
   - Автоматически собирается Docker образ
   - Образ загружается в Docker Hub с тегами `latest` и `branch-{sha}`
   - Через SSH подключение к VPS выполняются команды обновления контейнера

#### Требуемые GitHub Secrets:
- `DOCKERHUB_USERNAME` - логин Docker Hub
- `DOCKERHUB_TOKEN` - токен Docker Hub (с правами Read, Write, Delete)
- `VPS_HOST` - IP адрес или домен VPS
- `VPS_USER` - пользователь на VPS для SSH подключения
- `VPS_SSH_KEY` - приватный SSH ключ (ed25519)

#### Требуемая настройка на VPS:
- Git репозиторий в директории `~/vpn_bot` (или указанной в workflow)
- Файл `.env` с переменными окружения (НЕ копируется в Docker образ)
- Docker и Docker Compose установлены
- Публичный SSH ключ добавлен в `~/.ssh/authorized_keys`

#### Структура на VPS:
```
~/vpn_bot/
├── docker-compose.yml       # image: username/vpn-bot:latest
├── .env                     # Секретные переменные (не в git)
├── .git/                    # Git репозиторий
└── data/                    # Volume для БД (автоматически создается)
```

#### Настройка деплоя:
1. Отредактируйте `.github/workflows/deploy.yml` и убедитесь, что путь `cd ~/vpn_bot` соответствует вашей структуре на VPS
2. В docker-compose.yml на VPS измените:
   ```yaml
   vpn-bot:
     image: your-dockerhub-username/vpn-bot:latest  # Вместо: build: .
   ```
3. Убедитесь что `.env` файл находится в директории `~/vpn_bot` на VPS

## Типы промокодов

В боте реализованы несколько типов промокодов для разных целей:

### free_days
Добавляет дни к подписке пользователя.
- Пример: промокод на 7 дней добавит 7 дней к текущей подписке
- Применяется только если у пользователя есть активная подписка

### extra_traffic
Добавляет дополнительный трафик к Server A.
- Пример: промокод на 10GB добавит 10GB трафика к лимиту Server A
- Хранится в БД как `ru_extra_traffic`
- При отображении статуса складывается с `SERVER_A_LIMIT_BYTES`

### discount
Скидка на оплату подписки (процент).
- Применяется при обработке платежей
- Значение хранится как процент (например, 10 = 10% скидка)

### unlimited
Неограниченный доступ с ежемесячным обновлением трафика.
- Предоставляет безлимитный трафик на Server A
- Трафик автоматически обновляется каждый месяц
- Действует определённое количество месяцев

**Свойства промокодов:**
- `max_uses` - максимальное количество активаций (0 = неограниченно)
- `used_count` - текущее количество использований
- Каждый пользователь может использовать один промокод только один раз
